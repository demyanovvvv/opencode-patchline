# Работа с Patchline

[English](usage.md) · [Руководство](../../README.ru.md) · [Установка](../../README.ru.md#установка) · [Конфигурация](configuration.md) · [Контракты инструментов](../specs/tool-contracts.md)

## Обычный рабочий процесс

1. Найдите нужный код: `patchline_lsp` для символов, `patchline_grep` для текста,
   `ast_search` для синтаксических структур.
2. Прочитайте минимальный полезный диапазон через `read`. Ответ содержит путь,
   snapshot, Hashline-тег и якоря прочитанных строк.
3. Измените только прочитанный код, используя полученный snapshot. Не придумывайте
   теги, идентификаторы snapshot и якоря.
4. Проверьте результат и diff, затем запустите диагностику или тесты проекта.

Явный диапазон чтения поддерживает до 2 000 строк. Ограниченный ответ сообщает
следующий offset; для якорей доступны только действительно показанные строки.

## Точные правки

Вызовите `edit` со значениями из последнего `read`:

```json
{
  "filePath": "src/example.ts",
  "snapshot": "<snapshot returned by read>",
  "oldString": "<observed text>",
  "newString": "<replacement text>"
}
```

`newString: ""` удаляет прочитанный текст. `write` используется только для новых файлов.

## Hashline и многофайловые правки

Используйте `patchline_apply_patch` для Hashline-секций. Замените тег и номер
строки значениями, которые действительно показал `read`:

```text
[src/example.ts#<tag returned by read>]
PUT 12.=12:
+replacement line
```

`patchline_edit_batch` предварительно проверяет несколько snapshot-правок до записи.
`patchline_execute` выбирает точную правку, Hashline, batch или стандартный инструмент.
Проверяйте каждый ответ перед следующим вызовом. Подробнее: [контракт Hashline](../specs/hashline-contract.md).

## Обычный apply_patch и восстановление

Обычный `apply_patch` OpenCode доступен для больших файлов, больших изменений и
операций вне возможностей Patchline. После него заново прочитайте изменённые
файлы перед использованием snapshot-инструментов.

- `STALE_SNAPSHOT`: заново прочитайте файл и пересоберите правку по текущему тексту.
- `fallback_required`: используйте `nextTool`, указанный в ответе.
- `WRITE_PROTECTED`: существующий файл меняется через snapshot-правку `edit`.
- Отказ в разрешении: запросите нужное разрешение OpenCode. Для внешних абсолютных
  путей нужны `external_directory` и разрешение соответствующей операции.
- Ошибка совпадения контекста обычного patch: прочитайте диапазон и пересоберите patch.

Не обходите отказ записи через shell. Сохраняйте пользовательские изменения и
несвязанное форматирование. Подробнее: [решение проблем](troubleshooting.md).

## Проверка результата

Используйте `patchline_diagnostics` для настроенной команды диагностики, нативный
LSP при наличии и обычные проверки типов/тесты проекта. Команды требуют разрешения
OpenCode на конкретную операцию. `patchline_summary` показывает локальные счётчики.
Для проверки окружения выполните `node dist/cli.js doctor` из распакованного пакета.
