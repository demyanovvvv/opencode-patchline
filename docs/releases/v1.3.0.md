# Patchline 1.3.0

## English

OpenCode and Patchline now have separate version lifecycles. Installing Patchline preserves the installed upstream OpenCode version. Coordinated OpenCode upgrades invoke a host-only operation, keeping the plugin package version and its registration intact.

- OpenCode plugin SDK updated to 1.19.0.
- OpenCode 1.19.0 source adapters pass preflight.
- New `host-upgrade --opencode-version <version>` command.
- Host artifact selection for Windows, Linux and macOS x64/arm64.
- Regression tests for version preservation and script-launcher protection.
- CLI/TUI upstream comparisons, exact binary targeting, update locking and safe retention of locked Windows backups.

### Verification

Local Windows x64: 398 tests passed, 3 platform-specific tests skipped; typecheck,
lint, coverage, build, doctor, benchmark, package/plugin/installer/TUI/Hashline
smokes and dependency audit passed. The upstream OpenCode 1.19.0 native
`apply_patch` suite passed (28 tests). An isolated real host rebuild and
`opencode upgrade` cycle 1.19.0 → 1.18.35 → 1.19.0 preserved Patchline 1.3.0 and
byte-identical server/TUI configuration. UI update source adapters are verified;
an interactive UI click-through is not part of local verification. Cross-platform
SDK/adapter/native tests are configured in CI; platform-specific outcomes are
reported by that workflow rather than inferred from the Windows run.

Download the package archive and verify its SHA-256 using SHA256SUMS.txt. Extract to a permanent location, install runtime dependencies, and run `node dist/cli.js install --local --global --yes`. Restart OpenCode afterwards.

External package-manager upgrades can replace the integrated host. They cannot be intercepted by an inactive plugin. Reinstall the integration on the current upstream version after such an upgrade. Platform artifact selection is not a claim that every package-manager installation has been verified.

## Русский

Версии OpenCode и Patchline обновляются независимо. Установка Patchline сохраняет установленную upstream-версию OpenCode. Согласованное обновление OpenCode запускает отдельную операцию обновления хоста, сохраняя версию пакета и регистрацию плагина.

- SDK обновлён до 1.19.0.
- Адаптеры исходников OpenCode 1.19.0 проходят предварительную проверку.
- Добавлена команда `host-upgrade --opencode-version <версия>`.
- Выбор артефакта сборки для Windows, Linux и macOS x64/arm64.
- Регрессионные проверки сохранения версий и защиты script-launcher.
- Сравнение upstream-версий CLI/TUI, точный выбор бинарника, блокировка обновлений и сохранение занятых резервных копий Windows.

### Проверки

Локально на Windows x64: 398 тестов пройдены, 3 платформенных теста пропущены;
typecheck, lint, coverage, build, doctor, benchmark, package/plugin/installer/TUI/Hashline
smoke и аудит зависимостей пройдены. Upstream-набор native `apply_patch` OpenCode
1.19.0: 28 тестов пройдены. Реальная изолированная пересборка и цикл `opencode upgrade`
1.19.0 → 1.18.35 → 1.19.0 сохранили Patchline 1.3.0 и конфигурации server/TUI побайтно.
Адаптеры UI-обновления проверены по исходникам; интерактивное нажатие обновления
не входит в локальную проверку. Межплатформенные проверки выполняет CI.

Скачайте архив и проверьте SHA-256 по SHA256SUMS.txt. Распакуйте в постоянный каталог, установите runtime-зависимости и выполните `node dist/cli.js install --local --global --yes`. После установки перезапустите OpenCode.

Внешнее обновление менеджером пакетов может заменить интегрированный хост. Неактивный плагин не может перехватить такую операцию. После неё повторно установите интеграцию на текущей upstream-версии. Выбор платформенного артефакта не означает проверку всех вариантов установки.
